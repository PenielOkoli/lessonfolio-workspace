# Product brief and release targets

**Audience.** A junior secondary school teacher preparing tomorrow's lesson for pupils who need different amounts of support.

**Problem hypothesis.** A teacher may save time drafting activities but lose that time deciding whether suggestions suit the class and checking exactly what pupils receive. This is a hypothesis to test with a teacher.

**First promise.** A teacher can edit one objective, review two activities and publish a student-ready lesson with a worksheet. Publication should preserve the wording the teacher approved.

**Pilot question.** Can a teacher complete that workflow unaided and accurately predict whether a later edit changes the published copy? Record completion, time and confusion points with synthetic classroom material. No participant results have been collected.

## Decisions to revisit

- Local browser persistence makes the first lesson easy to follow. Student access across devices requires a shared published record and a read-only route. Teacher drafts need separate access controls.
- Rule-based activity drafts make the first approval workflow repeatable. Compare their instructional usefulness on real examples before choosing an API. An API key belongs on the server.
- A published edition captures a point in time. Republishing creates a new version number. This prototype retains the latest edition only.
